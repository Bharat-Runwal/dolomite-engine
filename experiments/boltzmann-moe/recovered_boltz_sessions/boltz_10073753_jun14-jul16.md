## (3) Compute cost of verification — essentially FREE

For MCQ scoring:
- **Standard logp**: 1 forward pass per (prompt + option). For K-option question = K forwards. Score each by mean log-prob of completion span.
- **Action verifier**: same 1 forward per (prompt + option). The energy `E_i^(t)` is **already computed inside the FET architecture** during the 6-iteration EGPT block forward — the verifier just reads cached `_last_energy_per_token` and sums.
- **Net extra cost: ~zero** (one O(B·T) sum over already-cached scalars).

For Best-of-N generation: same answer — score N candidates each with 1 forward, capture action during that same forward.

**Cost summary**: the action verifier is **architecturally free** for FET-family models. The 6× EGPT iteration is paid whether you use the verifier or not.

**On the R3 gating split — good question.** Yes, the current aggregator uses a **50/50 val/test** split per task. The val half decides both (a) whether `acc(action,val) > acc(logp,val)` and (b) whether the action lift on val exceeds 3σ above the random-tiebreak picker. Then the test half is what gets reported.

Can it be cheaper? Two angles:

1. **Per-question gating instead of per-task** — not possible with the current setup, because the gate is testing whether *the verifier as a ranker* works on this task distribution. You can't tell from one question whether logp's tiebreak was lucky or whether action would systematically beat it; that's a population-level property.

2. **Smaller val fraction (10–20%)** — viable but noisier. The bottleneck is the 3σ test: σ shrinks like 1/√n_val, so with val=10% of openbookqa (~50 questions) the 3σ bar is roughly 4–5pp; with 50% (~250 questions) it's ~2pp. Most of our action lifts are 5–11pp, so a 10–20% val would still gate openbookqa correctly but might miss borderline tasks (boolq +4.7pp on Hopfield base sits right at the edge). It would also let *more* test data carry through to the reported number, which is the actual reason to want it.

The cheap improvement: drop val to 20% and report test on the other 80%. I can add this as a `--val-frac` flag and re-run aggregation if you want to see how the headline changes. Probably not enough to change the qualitative picture (Boltz-MoE-Hopfield still wins), but it would tighten the test-side error bars.
