# bsaha200m — 200M HP sweep for sparse Boltzmann-MoE (12 arms)

A **screening sweep**, not a results grid: 12 arms at 200M total / 15.73B tokens, cheap enough to
run in a day, to find good hyper-parameters for sparse Boltzmann-MoE before spending 400M compute.

Generated by `_make_configs.py` (one template + patched deltas — edit that, not the `.yml`s).
Verify with `_verify_params.py`.

## Composition — both arms have standard MoE

| arm | layers 0–7 | layers 8–11 | MoE everywhere? |
|---|---|---|---|
| `s12_stdmoe` | softmax attn + **std MoE** (all 12 layers) | — | **yes**, 12 std-MoE blocks |
| `s8e4_bmoe` | softmax attn + **std MoE** | energy attn + **EnergyFF_BoltzmannMoE** | **yes**, 8 std + 4 Boltzmann |

`s12` / `s8e4` name the **attention** split (12 softmax / 8 softmax + 4 energy), **not** whether
MoE is present. Every layer of every arm is a mixture; there is no dense FFN anywhere. Both use
`top_k: 2`.

## Geometry (identical for all 12)

4 GPUs x `micro_batch_size: 4` x `gradient_accumulation_steps: 8` x `sequence_length: 4096`
= **524,288 tok/step** x **30,000 steps** = **15.73B tokens**.

`ga=8` is forced: a true 16.0B at 30k steps would need `ga=8.14`, which is not an integer.
Cosine LR, 500 warmup steps, identical across all 12 — the paper's own `tab:status` warns that a
gap measured *across* LR schedules (cosine vs WSD) is not controlled, so the schedule is held fixed.

## The four proxy/routing knobs, and what each should do

The sparse path cannot route on the true energy: a Boltzmann expert's score IS its energy, and the
energy is only known after its projection. So a cheap **proxy** predicts all K energies, nominates a
shortlist, and the shortlist's exact energies re-rank to the final top-2. At 400M/K=64 this proxy
achieved only **`proxy_topk_agree` = 0.63–0.68** — it picks the true top-2 about two-thirds of the
time — and the paper independently records Hopfield proxy fidelity as "**poor**: +0.13 to +1.66 PPL".
That is the defect these arms target.

**`proxy_rank`** (base 16, arm 32) — rank *r* of the low-rank router. The proxy scores each expert on
a rank-*r* projection of the token, costing `K*d*r` MACs instead of a full projection. Higher *r* =
a more faithful ranking, at `K*d*r` cost and `+2.6M` params. Expect: the single largest lever on
`proxy_topk_agree`; watch whether train loss follows, because agreement is a means, not the goal.

**`proxy_out_dim`** (base 512, arm 1024) — the proxy evaluates only *m* rows of each expert's
projected matrix. For Hopfield the energy is a mean of I_e **non-negative** terms, so an *m*-row
subsample is unbiased with relative error ~`1/sqrt(m)` — ~4% at m=512, ~3% at 1024. Cheap accuracy,
`+1.0M` params. (The code notes this is valid *only* for Hopfield: for `w1w2` the terms have random
sign and the same subsample has ~210% error — the reason the sparse arm is Hopfield, not `w1w2`.)

**`proxy_loss_coef`** (base 0.01, arm 0.05) — weight on the KL that distils the proxy against the
exact routing distribution. Free (no params, no forward cost). Expect better agreement; risk is that
a large coefficient competes with the LM loss for capacity.

**`sparse_candidates`** (base 2, arm 4) — *p*, how many experts the proxy nominates. Their exact
energies both re-rank to the final top-2 **and** supply *p* exact terms to the softmax denominator.
The code measures why *p* matters: proxy *selection* alone costs +0.0165 bits/byte, but a
proxy-*filled denominator* costs **−1.52 nats**. Raising p to 4 is the most direct accuracy fix and
the most expensive one — it trades away the speedup, since cost scales with `cf*p`.

**Also swept: `proxy_init`** (base `random`, arm `svd`). The code records measured top-2 agreement of
**0.554 (SVD) vs 0.038 (random)** on a trained 1B checkpoint — a 6.2x improvement. **The 400M run
left this at `random`**, so this arm may be the cheapest large win in the sweep: zero params, zero
forward cost, a better starting point for the same distillation.

## Read these on loss and WikiPPL only

At 400M/31.5B, MMLU was already at the chance floor (.2455–.2765) and GSM8K at floor (1.4–3.9%) for
all five arms. At 200M/15.7B **every downstream benchmark will be noise**. Rank these arms on
`lm_loss` and wikitext word-PPL; treat MMLU/GSM8K as sanity checks, never as a ranking.

**Then confirm the top 2 configs at 400M.** LR optima shift with scale, so a 200M winner is a
hypothesis, not a result. Note also **n=1 per arm** — no seeds, so a <0.5pp difference between two
arms here is not resolvable.

## Requirements

Needs three infra commits absent from `nima/main` (cherry-picked onto this branch):
`_no_split_modules` tf-4.57/5.x compat (without it the model will not even instantiate), the
repulsion-pair device fix, and the torch<2.9 `aten_distributed_optimizations` guard (which
otherwise blocks all multi-GPU). Run on `.venv-nima` (transformers 4.57.1) — 5.1.0 silently
clobbers the tied `wte`, and every config sets `tie_word_embeddings: true`.

Data paths point at `/proj/datasets/ndehmamy-dataset-rescue` (hard links to the full corpus; the
original `granite-4-datasets-megatron-merged` was purged 2026-09-22). `data_cache_path` is a fresh
`cache-bsaha200m` — a new tokenizer/seq combination must not reuse a cache built for another.

Submit on `-q normal -G grp_ebm`, **not** `-q preemptable` (which burned ~30h with zero steps on
the FET runs). Check `bqueues` before submitting all 12 — the queue has been saturated recently.
